[ATTACKBOX USER MANAGEMENT]

1. ID SPECIFICATION
- SQLite autoincrement primary key: users.id INTEGER PRIMARY KEY AUTOINCREMENT (int64)
- STRICTLY NO SNOWFLAKE: Single-controller design, SQLite native autoincrement guarantees physical uniqueness without clock-skew/NTP drift or JS 64-bit integer truncation
- Global anchor: JWT sub, sandbox byUser[uid], slot allocation, audit_logs.user_id all bind to this numeric id

2. AUTHENTICATION & LOGIN
- STRICTLY EMAIL ONLY: Login credential must be registered email + password
- No username login: Non-email logins rejected with HTTP 400
- Allowed email domains: @qq.com, @foxmail.com, @gmail.com, @outlook.com, @hotmail.com, etc.
- Anti-enumeration: Send-code returns success regardless of email existence
- Timing defense: Constant-time dummy bcrypt calculation when user not found

3. USERNAME CONSTRAINTS
- Default format: USER_<id> (e.g. USER_1) derived from autoincrement id if unset
- Uniqueness: UNIQUE NOT NULL COLLATE NOCASE, case-insensitive collision check across entire db
- Modification: 2-24 characters, pre-checks duplicate before write (HTTP 409 on collision)

4. JWT & SESSION REVOCATION
- Ed25519 compact JWT issued by Control private key
- Active invalidation: users.token_version (int), JWT carries 'ver' claim
- Auto-increment token_version on: password change, account suspension (status=0), forced kick
- Tokens with ver < db.token_version rejected with HTTP 401

5. DATABASE CRUD APIS (control/control_database.go)
- CreateUser(username, hash, email, role): validates uniqueness, writes atomic row
- EnsureAdminUser(username, hash, email): checks/patches/bootstraps initial admin
- GetUserByID(id): query by int64 id
- GetUserByEmail(email): login authentication lookup
- GetUserByUsername(username): username collision pre-check
- ListUsers(limit, offset): paginated user list
- CountUsers(): total user count
- UpdateUsername(id, newUsername): updates username after collision pre-check
- UpdatePassword(id, newHash): updates hash + increments token_version
- UpdateStatus(id, status): toggles active/suspended + increments token_version
- UpdateRole(id, role): updates admin/user role
- DeleteUser(id): physical deletion
