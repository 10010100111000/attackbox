# Docker 靶机：小步迭代计划

状态：计划，尚未实现。用户管理、学习路线和真实 Worker 单机验收已存档至 `912ff40`。

## 已确认的方向

- 保留现有攻击端，本阶段不重写 Btrfs 运行时。
- 新增统一的 Docker 靶机模板管理。教学环境由管理员准备镜像，开源挑战环境记录项目来源；学习页与挑战页都只关联模板，不分别维护镜像配置。
- 第一版只做独享实例，不做共享、投票重置、使用租约或维护排期。
- 后续运行接入先核对并复用 Worker 的现有网桥、地址分配与规则，不默认创建另一套冲突网络，不承诺同网桥下的用户级网络隔离。
- 独享指容器状态与重置归属本人，不等同于网络完全隔离。保留基本运行边界：不开放任意特权、host 网络、宿主挂载和 Docker Socket。
- 学习上下文通过预置镜像及模块内跨章节复用承载，不在切换章节时自动执行初始化脚本。
- 后续按全新数据库部署设计，不为旧数据实现兼容迁移；清库在实际部署时执行，本次仅规划，不清理现有数据库。

## 下一轮：仅做靶机模板基础管理

交付一个能实际维护模板的后台页面与 API，不调用 Docker、不连接远程节点、不改网桥或现有学习／挑战页面。

### 页面与交互

后台“环境管理”下新增“靶机模板”：

1. 列表展示名称、镜像、启用状态；支持搜索、查看／编辑、新建。
2. 新建页填写名称、简短用途说明、镜像引用、可选来源项目链接、预期服务端口、访问说明。端口记录容器内端口与 TCP／UDP 协议，不配置公网映射。
3. 镜像使用明确 tag 或 digest；这一轮只验证格式，不拉取镜像，也不虚报镜像存在或服务健康。
4. 首次保存才产生记录；保存后停留编辑页并提供明确反馈。取消新建不会留下空记录。
5. 启用仅表示以后允许在学习／挑战编辑器中选择，不表示容器正在运行。停用不产生容器停止操作。
6. 保留未保存修改提醒、必填与端口重复校验、加载失败和保存失败状态。并发修改返回冲突，保留本地输入供用户复制或重新编辑。

布局沿用现有后台：基础信息与镜像在主栏，服务端口和访问说明按用途分组；输入框宽度按字段内容设置，不以大文本框堆砌配置。没有容器运行能力时不显示“启动”“重置”假按钮，也不展示虚构运行统计。

暂不加入环境变量密钥、镜像构建、Compose、多容器、在线终端、健康检查执行或测试启动；资源策略与运行时限在真正接入 Worker 前单独设计。

### 数据与接口

增加 `target_templates`，只保存上述可维护的静态信息，以及启用状态、创建／更新时间和并发修改标识。端口保存为有校验的结构化数据，不接受任意 Docker 参数。仅管理员可读写模板管理接口，输出和错误不得暴露未来的运行凭据。

| 方法 | 路径 | 职责 |
| --- | --- | --- |
| GET | `/api/admin/target-templates` | 搜索与分页列表 |
| POST | `/api/admin/target-templates` | 首次保存并创建 |
| GET | `/api/admin/target-templates/:id` | 编辑详情 |
| PUT | `/api/admin/target-templates/:id` | 保存、启用／停用；检查修改标识 |

第一轮不提供硬删除，使用停用；待学习和挑战开始引用模板时，再根据引用关系决定删除规则。不引入配置历史版本或实例表。

### 本地验收标准

- 管理员可以新建、保存、编辑、停用和恢复模板；打开新建页不产生记录。
- 空名称、错误镜像格式、无效来源 URL、非法／重复端口均有明确反馈。
- 非管理员和未登录用户不可访问管理 API；写操作检查请求来源。
- 并发保存不能静默覆盖；模板停用不被表述成“目标已停止”。
- PostgreSQL 集成与 Chromium 端到端验证上述操作，完成 TypeScript 和生产构建检查。不进行远程验收。

完成上述范围后先提交并评审结果，不顺带扩展到 Docker 调度。
