# Docker 靶机运行接入与部署测试

已接入 Worker 网络和生命周期、Nuxt 独立 Target RPC、数据库实例记录、用户接口，以及学习章节和挑战详情页运行卡片。此轮没有远程部署，没有执行生产数据库迁移。

## 更新步骤

1. 安装 Docker Engine 27.5+，使用 iptables 后端，准备 iproute2、iptables、nftables。
2. 编译新版 Worker，在实际 node.yaml 开启 network.docker_targets.enabled，按 [网络配置](worker-docker-network.md) 确认独立且不冲突的靶机网段。保留持久状态目录。
3. 在 web 目录使用部署环境 DATABASE_URL 执行 npm run db:migrate，再 npm run build 并重启 Nuxt。迁移 0009_target_instances 增加实例归属、快照和操作版本。
4. 确认 Worker 已注册且心跳在线。第一次启动只支持单节点，或者已有同节点攻击环境；不返回跨节点不可达地址。
5. 管理员创建或启用模板，关联已发布章节／挑战；用户登录后使用运行卡片启动、刷新或停止。

API：GET /api/targets 使用 kind=chapter、moduleSlug、chapterSlug，或 kind=challenge、challengeId 查询；POST 同路径使用相同上下文和 action=start。停止使用 action=stop 和返回的实例 id，仅允许所属用户操作。接口不接收浏览器自选镜像、Owner、Node 或 Docker 参数，写请求检查来源。

同用户模块默认靶机跨章节复用；章节自定义和挑战各有归属。重复启动使用同 ID；停止后下一次启动生成新 ID。模板停用禁止启动，已有实例可刷新和停止。模块／章节访问校验沿用学习解锁权限。原始服务端配置快照不直接返回浏览器。

实例采用数据库唯一归属和操作 revision 防止多标签页覆盖新状态。Worker 超时、离线或 RPC 断开保留实例记录，用户刷新后按同 ID 查询对账；没有后台轮询自动销毁，也没有 TTL。运行中容器不会因为 Control 重启而清理。目标状态使用独立 Worker 心跳能力信号，不混入 Btrfs 清单。

当前页面有界面级忙状态、刷新与运行时状态，定期轮询仅在页面打开时进行。仍有后续边界：管理员统一运行实例页、账号封禁联动回收、全站个人环境列表和后台持续对账尚未加入；课程下架或关联范围变化后，旧实例可凭已知 id 调用本人停止接口，尚无统一界面处理此情况。因此本轮先做有人值守测试，并主动停止测试实例。

## 你这次的测试重点

- 登录用户启动实际镜像，确认服务就绪与地址，沙箱访问靶机及靶机反连。
- 同模块切章节复用，同模板不同挑战不会共用实例。
- 多标签页重复启动、停止期间刷新、断线后刷新，不能出现重复容器或假停止。
- 停止后再次启动新实例；Worker 和 Nuxt 重启后可恢复归属。
- 未登录、不同用户、未发布内容、未解锁章节不能启动或越权停止。
- 镜像不存在、UDP-only 无健康信号、节点离线时能保留可解释状态。

本地通过：83 项 Node 测试、TypeScript、Nuxt 生产构建、Go 测试和真实 Docker 生命周期测试。数据库迁移／API／浏览器端到端与跨桥连通性尚未在真实部署验证，不将构建通过当作上述验收通过。
