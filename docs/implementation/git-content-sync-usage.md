# 手动 Git 教程同步使用说明

已实现：单文件解析、本地导入服务、GitHub 私有仓库手动拉取、差异预览/改名关联、确认导入、新的 Git 管理模块详情，以及带权限校验的图片访问。没有定时拉取、Webhook、自动发布或前端状态轮询。

## 部署

1. 部署新版 web，并执行 `npm --prefix web run db:migrate`，应用 0011、0012 两个迁移。无需修改 Go Worker。
2. 设置环境变量 `CONTENT_DATA_DIR=/var/lib/attackbox-web/content`。这是持久目录，不能放进每次发布会替换的 `.output`；确保 `attackbox` 服务用户可创建和读写此目录。
3. 用 `openssl rand -hex 32` 在部署机器生成独立密钥，写入服务器环境变量 `CONTENT_CREDENTIALS_KEY`，不要写入 Git。保留该密钥用于后续解密，丢失后需重新填写仓库 Token。
4. 重启 web 服务。环境变量示例在 `deploy/web.env.example`。

备份 PostgreSQL、持久内容目录及部署密钥。Token 用 AES-256-GCM 加密存入数据库，读取配置只返回是否已配置，不回传 Token 或密文。临时快照目录权限为 0700，文件为 0600。

## 首次导入

1. 后台“学习模块”→“检查 Git 更新”，进入 `/admin/content`。
2. 填入 `owner/repository`（或标准 GitHub HTTPS 链接）、分支、教程目录；目录留空表示根目录。该目录第一层每个 MD 是一个模块，README.md 不导入。
3. 填写仅授权此仓库 Contents: Read-only 的 fine-grained PAT。公网提交凭据需要 HTTPS。保存配置不会连接 GitHub。
4. 点击“测试连接”，确认凭据、分支和目录；点击“拉取并预览”读取固定 Commit 的内容快照。每次拉取最多两分钟，受文件数、大小限制；失败后可以手动重试。
5. 检查模块、章节和题目预览。未知分类请先在后台建立或修改 MD 的 category 字段。
6. 如需接管旧模块，展开“关联已有内容”，明确选择旧模块并确认，再关联章节/题目；相同标题与题干的已有内容在明确接管的模块内自动匹配。不会仅凭模块同名覆盖旧记录。
7. 点击“确认导入”。新模块保持未发布；已经发布的模块内容会立即更新，发布状态及靶机、前置推荐配置保留。
8. 进入模块详情检查内容，设置运行配置并发布。

选择错误的目录或仓库不会自动删除原模块；缺失来源只提示，旧内容继续保留，可独立下架。

## 修改与改名

- 相同来源的正文、排序、答案和时长更新保留原 UUID、URL、已通过题目及完成记录。
- 文件、一级标题或题干改名，使用预览里的关联选择保留身份。关联一对一，章节/题目不能关联到别的模块/章节。
- 移除已有章节或题目会阻断导入，当前版本不实现隐式级联删除。请恢复文件内容或完成正确的改名关联。
- 预览后线上内容、运行配置或仓库设置改变，确认导入会要求重新拉取；不会覆盖新配置。
- 同一个预览重复确认返回同一结果，不重复创建模块。预览有效期一小时。
- 已导入内容独立于 GitHub；仓库暂不可达不影响学员读取。

## 后台功能边界

Git 管理的模块使用新的只读详情页，保留发布/下架、模块与章节靶机配置、前置推荐。旧的完整保存 API 拒绝修改 Git 管理模块，运行配置使用独立接口，禁止夹带正文或题目字段。

尚未关联 Git 的旧模块仍可通过隔离的 LegacyModuleEditor 编辑，以便过渡；新建入口改为模板下载和 Git 导入。全部接管后再删除旧编辑组件，当前不会自动清理旧数据。

图片准备在数据库事务之前完成，使用哈希命名的持久文件；图片变化参与模块变化检测。正文通过资源映射展示图片，不替换命令示例里的同名文本。受限章节图片经服务端检查登录/进度权限，不能靠猜 URL 匿名获取；模块介绍主动引用的图片视为公开资源。所有资源当前使用 private/no-store，暂不做 CDN 缓存。

## 失败与临时文件

GitHub 拉取、图片准备在数据库事务之外；正式内容、来源关联、题目和资源引用在同一短事务提交。失败不部分发布，最多留下未引用的资源文件。

页面不自动查询。网络中断后，点击“查询最近预览结果”读取最近完成的拉取/导入预览；不要根据浏览器超时猜测数据库是否提交。页面不要求管理员填写或记忆内部预览 ID；查询最近预览不会重新拉取仓库，也不会重复导入。

已导入预览会自动清除对应临时快照；未导入或过期的预览可通过“清理预览”显式删除。该操作不删除已导入模块。未引用的持久图片文件清理尚未实现，不做自动删除。

## 本地验证

- `npm --prefix web run content:check -- ../docs/content-template`
- `npm --prefix web test`
- 本地独立 PostgreSQL 与已运行的 web：设置 `CONTENT_TEST_DATABASE_URL`（必须是 localhost 的 `_test` 库）、`CONTENT_TEST_BASE_URL`、`CONTENT_DATA_DIR` 和相同的 `CONTENT_CREDENTIALS_KEY`，运行 `npm --prefix web run test:content-sync`。

集成覆盖重复导入、进度保留、答案修改、改名、运行配置保留、禁止删除与旧接口写入、图片权限、凭据不回显及浏览器页面。GitHub API 使用模拟响应；真实私有仓库需要管理员配置后进行实际连接验证。
