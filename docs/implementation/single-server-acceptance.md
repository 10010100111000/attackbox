## 1. 只读预检

在仓库根目录运行：

```bash
ssh laji@100.69.228.63 'bash -s' < scripts/remote_sandbox_preflight.sh
```

脚本检查当前用户、非交互 sudo、内核、工具、Btrfs、Cgroup、服务和监听端口，不读取密钥、数据库连接串或服务 Environment，不安装软件或改变服务。

随后定位实际应用 release、数据库配置、Worker 配置与实例清单。Worker 启动包含残留实例和网络清理，应先确认现有 Worker 和活跃实例，再确定维护切换顺序；同一节点始终由一个控制端负责。

## 2. 准备单机验收部署

- 使用独立测试数据库和测试账号，不清空现有学习库。应用全部增量迁移，包括 `0003_sandbox_identity.sql`、`0004_sandbox_node_settings.sql`。
- 将仓库新代码构建到新 release 目录，保留旧 release、受保护的配置及数据库备份；先核对机器架构与 Node/Go 版本。
- Nuxt 用单个常驻进程；显式设置接入与调度开关、独立集群身份和持久 Ed25519 seed。节点白名单只包含本次验收节点，最初并发为 1。
- 核对 Worker 的 Btrfs 金盘、实例目录、Cgroup、宿主网络与 VNC/MATE 依赖。以实际预检结果确定路径与服务名，不直接覆盖未知配置。
- 使用既有、已完成脱敏的只读金盘或按 Worker 的金盘构建流程准备，核验后启动 Worker。

无需先配置公开域名即可进行封闭验收。例如 Nuxt 监听 `127.0.0.1:3031`，Worker 数据网关监听 `127.0.0.1:18443`，Worker 控制 URL 为 `ws://127.0.0.1:3031/cluster/connect`，登记数据地址 `ws://127.0.0.1:18443`，允许前台 Origin `http://127.0.0.1:3031`。

从验收客户端建立 SSH 转发：

```bash
ssh -N -L 3031:127.0.0.1:3031 -L 18443:127.0.0.1:18443 laji@100.69.228.63
```

浏览器访问 `http://127.0.0.1:3031`。这是 localhost 联调配置；公网正式访问按 [沙箱接入说明](sandbox-node-onboarding.md) 使用 HTTPS/WSS 和实际站点 Origin。

## 3. 必测流程

1. 管理员确认节点在线；保存设置、重启 Nuxt 后核对配置仍存在。并发上限为 1 时第二个用户收到资源不足，首个用户重复启动复用同一实例。
2. 从真实章节启动 CLI，执行 `id`、`pwd`、创建测试文件；打开第二个终端确认同一文件可读。
3. 切换 GUI，等待 MATE 实际启动，验证画面、键盘、鼠标和同一份 home 文件；CLI/GUI 同时存在只占一个实例。
4. 调整、收起、关闭再打开面板，验证连接不被面板操作重建。主动断开数据连接后重新签发 Ticket；CLI 明确开启新 Shell，GUI 复用现存桌面。
5. 排空节点后保留已有实例，拒绝新分配。改变内存、PIDs、TTL/Idle 只作用于后续新实例，核对实际 Cgroup 文件与 Worker 截止时间。
6. 用户和管理员分别释放测试实例，确认进程、快照、网络、Cgroup 清理完毕；界面与资源占用同步消失。
7. 在专用测试实例验证创建/清理失败、控制断线、TTL/Idle、Worker 重启及 Control 重启后的清单核对。RPC 超时不能直接显示资源已释放。
8. 核对越权请求、过期和重放 Ticket 被拒绝；轮询和画面更新不延长 Idle，真实键鼠与终端输入能更新活动时间。
