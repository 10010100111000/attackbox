# Compose 准备任务：取消、重试和强制重建

状态：本轮已接入 Worker、控制 API 和管理员界面。保留手动查询，不新增页面轮询、任务调度服务或按任务运行的后台扫描器。

## 管理员交互

- 未准备：保存模板后点击“准备部署”，仍复用已存在的镜像与构建缓存。
- 准备中：可手动查询或取消。取消请求先显示“取消中”；只有下载／构建退出后才报告“已取消”。取消不会释放学员靶场，也不删除任何镜像。
- 失败／已取消：点击“重试准备”分配新任务身份，不复活旧任务。若上次是强制重建，重试继续采用刷新模式。
- 已准备：可手动查询，或明确点击“强制重建”。确认后重新拉取 image 服务镜像，本地 Dockerfile 使用 `--pull --no-cache`，跳过同源镜像缓存。不会修改原始包、删除旧镜像或推送 Registry。
- 有旧产物时，新任务的进度与“现有部署可用”分开展示。失败、取消、繁忙或磁盘压力拒绝都保留原部署。重建成功只影响后续新实例，原实例继续使用创建时的部署 ID 和租期。

任务正在执行或结果未知时，部署来源／入口／变量修改需先查询或取消当前任务；名称和说明等元数据仍可保存。取消和查询不要求先保存编辑区，避免“修改了表单后不能取消任务”。节点离线不能确认已取消，需要恢复节点后查询或取消；不会把离线当作工作已停止。

强制重建可能得到相同镜像摘要，此时部署 ID 可以复用，不人为制造版本。失败后界面的准备记录只返回阶段及安全错误说明，不包含原始 CLI 输出、部署变量或凭据。

## 任务身份与并发

准备记录包含 `attempt_id`、`mode`、`version`。每个模板修订／节点仍只有一条准备记录，未新增历史版本编辑器或任务历史列表。

- `deployment_id` 和 `boot_id` 表示最近已确认的可用产物及节点代次，不再把“任务正在准备”误认为“原部署不可用”。新任务成功才切换该引用；调度仍核对当前模板修订与 Worker Boot ID。
- 每次重试／重建生成新 attempt ID；`expectedAttemptId` 防止旧页面取消或重建另一名管理员的新任务。重复准备不会重复执行同一个任务。
- 所有 RPC 结果按准备记录、attempt ID、version 做比较更新。迟到的状态响应、取消响应或前次重建结果不能覆盖新任务；竞争失败返回数据库当前结果。
- Worker 用独立准备协调器执行一个任务，实例启停不占用这把任务锁。取消使用与停止相同的保留通道，启动通道已满时仍能取消准备。
- 取消先于准备到达时记录取消意图，迟到请求不会启动。最近任务缓存有界为 256 条；终态至少保留 3 分钟，只有之后才可淘汰。入场请求最多允许过去 2 分钟、未来 30 秒，过期请求无法重新激活已淘汰任务；控制端和 Worker 应保持时间同步。这是请求检查，没有新增清理定时器。
- Worker 失去任务内存后，可核验原部署产物，不能把丢失的强制重建误报为成功。未完成任务显示待确认，明确取消后再重试；已完成任务可通过原产物恢复可用确认。

取消复用 context 传播到 HTTP 下载、镜像拉取和 Compose 构建。Docker CLI 使用独立进程组，取消会一起终止本次命令的插件子进程，并限制管道等待时间，避免仅杀父进程后后台仍在构建。终态发布前执行临时目录清理并释放准备容量；Worker 关闭也会取消未完成任务。超过既有 30 分钟总期限报告失败，不增加无限自动重试。

## 部署与协议

从空库执行 `npm --prefix web run db:migrate`；不提供旧数据库转换。

控制端和 Worker 同次升级到 **Compose 协议 2**。旧协议 1 不再被视为兼容节点，避免把取消或强制重建发给会忽略它们的旧 Worker。新消息 `compose_prepare_cancel`，准备消息新增 `rebuild` 和 `requested_at`；其余启动／释放归属与网络启用门槛不变。

节点磁盘熔断继续拒绝新准备／启动；状态查询和取消可执行。节点处于 draining 时允许查询和取消，不接受新准备或重建。所有权、Worker Boot ID、连接身份和响应类型仍严格绑定。

## 验证

- Go race／vet：取消与完成竞争、新任务重试、取消先到、归属校验、缓存边界和请求过期、取消保留通道、强制刷新 image 与 build、CLI 刷新参数、旧产物不被修改。
- 真实本机 Docker 夹具继续验证普通构建、目录副本、多用户与释放；强制拉取／跳过缓存通过 CLI 与引擎契约测试，不为测试从公开 Registry 强制拉取未知镜像。
- `npm --prefix web test`、TypeScript 与生产构建。
- `npm --prefix web run test:compose-labs`：使用隔离 localhost `_test` PostgreSQL、模拟 Worker 和 Chromium。新增测试覆盖取消、失败重试、强制重建、迟到响应竞争、重建期间新学员使用原部署、成功后新实例使用新产物、旧实例释放继续引用旧产物，及后台按钮交互。环境变量沿用 [平台接入测试](compose-platform-integration.md#验证与后续)。

代码已统一为 Compose 模型；真实 Btrfs／veth 网络验收仍需在部署主机执行，本轮未连接 VPS。
