# 挑战内容与分阶段 Flag

已实现挑战内容闭环，环境仍只关联现有靶机模板，不调用 Docker、不改网桥，也不进行远程验收。

## 管理端

- `/admin/challenges`：列表、名称／分类搜索、发布状态、阶段数量、编辑与删除。
- `/admin/challenges/new`、`/admin/challenges/:id`：标题、简介、Markdown 正文与预览、真实分类文本、难度、靶机模板，以及有顺序的阶段列表。
- 阶段配置标题、Markdown 任务说明、标准 Flag、可选提示；支持添加、移除和上下排序，最多 30 阶段。
- 新建页不创建记录，首次保存才创建。保存为草稿会下架；保存并发布原子保存全部内容。发布要求正文和至少一个带 Flag 的阶段。
- Flag 可由管理员直接查看和修改，不配置复杂匹配规则。默认忽略首尾空白、区分大小写，无需固定 flag{} 前缀。
- 保存有未保存离开提醒和并发修改保护。保留阶段 ID，新增阶段后重新读取 ID，避免下一次保存重建阶段并清掉进度。
- 模板新关联要求启用；已停用的原引用允许保留，前台显示暂不可用。没有容器启动按钮或模拟运行状态。

## 学习者端

- `/challenges`：已发布挑战列表、真实分类／难度筛选和名称搜索，登录后显示本人阶段进度。
- `/challenges/:id`：SSR 正文、目标环境说明、分阶段任务、折叠提示与 Flag 提交。
- 所有阶段任务可阅读，提交按顺序解锁；后续阶段不能通过直接调用 API 越级提交。
- 每阶段通过后记录到账号并显示完成状态，不再显示 Flag 输入；所有当前阶段完成后显示挑战完成。
- 错误 Flag 不扣分，不展示排行榜；有提示时引导查看提示。访客可以阅读，但提交需登录。
- 已通过阶段更新 Flag 不自动撤销记录；新增阶段需要继续完成，删除阶段会删除该阶段记录，完成比例按当前阶段计算，不宣称永久成就。

## 安全与持久化

挑战、阶段、用户阶段通过记录和提交限流分别保存于 `challenges`、`challenge_stages`、`challenge_completions`、`challenge_attempt_limits`。

标准 Flag 原文仅用于管理员配置回显，服务端使用 HMAC 和恒时比较判题；公开详情和列表显式选择字段，不返回 Flag、摘要或镜像配置。不会保存用户提交的错误 Flag 文本。正确记录以用户＋阶段唯一，重复提交幂等。

每用户每挑战每分钟最多 20 次未完成阶段提交，限流状态在 PostgreSQL 中持久化；失败尝试也提交计数，不能通过事务回滚绕过。判题与内容编辑共享挑战行锁，配合用户维度锁处理并发，避免编辑和最后阶段提交交错。

草稿、下架挑战不公开也不能判题；下架保留完成记录，重新发布可恢复。删除挑战需确认并清理阶段及记录。所有私人进度响应禁止共享缓存，账号切换清理挑战缓存；写接口校验请求来源。

## 接口

- 管理员：GET／POST `/api/admin/challenges`，GET／PUT／DELETE `/api/admin/challenges/:id`。
- 公开：GET `/api/challenges`，GET `/api/challenges/:id`。
- 登录提交：POST `/api/challenges/:id/attempt`，只接受 `stageId` 和 `flag`，用户身份取会话。
- 私有记录：GET `/api/me/challenges`，只返回当前账号在已发布挑战中的阶段进度和最近通过时间，供后续个人空间复用。

列表与详情分别使用摘要／完整类型，不将管理员字段或答案混进公开任务契约。数据库定义和 Drizzle snapshot 已同步；按全新库规划，不实现旧数据兼容逻辑。

## 本地验证

`npm run test:challenges`，配置隔离的本机 `_test` PostgreSQL 和 Nitro：`CONTENT_TEST_DATABASE_URL`、`CONTENT_TEST_BASE_URL`。

覆盖发布隔离、答案与镜像配置不泄露、阶段锁、错误／大小写／首尾空白、重复和并发提交、账号隔离、限流与窗口恢复、修改 Flag 保留进度、停用模板保留关联、管理员浏览器创建／编辑／再保存保留阶段 ID，以及学习者完成、刷新、访客登录入口和下架隔离。

本轮验证通过：82 项常规测试、挑战接口与 Chromium 端到端流程、3 项原有内容／学习进度测试、原有学习浏览器回归、TypeScript、生产构建和 Drizzle 无差异检查。仅使用本地临时 PostgreSQL 与应用，完成后清理。
