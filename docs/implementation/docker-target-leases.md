# Docker 靶机租期与自动释放

## 职责

- Nuxt/Nitro 控制端负责鉴权、解析课程/挑战的模板、分配实例 ID 与节点，并在 PostgreSQL 中保存绝对到期时间。
- Go Worker 是唯一操作 Docker 的执行方，负责创建、启动、删除容器与匿名卷。控制端不直连 Docker，浏览器只发意图。
- 浏览器展示服务端到期时间，不承担回收；关闭页面、没有键鼠活动、控制端断线都不延长租期。

## 第一版规则

从分配实例开始固定 60 分钟，镜像须提前准备。重复启动请求复用同一 ID 和到期时间，不能续期；暂不提供续期和活动保活。沙箱租期与 Docker 靶机租期独立。

租期写入数据库 `target_instances.expires_at`，通过启动协议传递为 `expires_at`，并写入 Worker 本地实例记录。相同实例的到期时间不可修改；客户端传入的到期时间不参与分配。

Worker 启动时立即扫描，此后每 5 秒扫描；扫描与控制连接生命周期解耦。到期先持久化 stopped 意图，然后强制删除已确认归属的容器与匿名卷，检查容器确实不存在后才返回 stopped。失败保持 cleanup_pending，并在后续扫描重试。已确认完成的记录保存 cleaned 标记，避免每次扫描重复删除与写盘。启动、查询也执行同一到期检查，迟到请求不能复活旧 ID。

控制端每 15 秒对已到期且尚未确认停止的数据库记录进行对账，使用现有停止协议并发上限 4，不依赖学员访问，也不依赖模块仍然发布。节点离线只意味着待确认，不等于已停止。只有确认 stopped 后，下一次启动才会分配新的 ID 和租期。

前端只在进入页面时读取一次状态，启动和释放后使用操作响应更新，不进行定时轮询。倒计时每秒在本地计算，不产生请求；归零显示“租期已到期”，不在客户端擅自声明释放成功。管理员镜像状态也仅由明确点击查询，不自动轮询。

## 故障与部署

Worker 断开控制连接仍回收。Worker 进程本身停止时无法执行删除；重启后从本地持久化记录继续回收。Docker 不可用、实例操作阻塞等故障可能延迟回收，因此扫描周期不是严格删除时限。主机时钟应同步。

需要同时部署新控制端和 Worker，并执行 `npm --prefix web run db:migrate`。0010 增加租期字段及索引；既有数据库记录默认立即到期，旧 Worker 无期限的本地记录也按到期处理，不授予无限时长。

## 验证

- Go race：到期前保留、到期后删除、删除失败后持久化停止意图、重启后重试、重复启动不能续期、旧 ID 不能复活、他人不能触发删除、迟到请求不能创建容器。
- 本地 PostgreSQL 与模拟 Worker 集成：首次分配 60 分钟，重复启动保留截止时间，无页面访问时 Nitro 后台对账停止实例，确认后重新启动生成新 ID。
- 集成命令：`CONTENT_TEST_DATABASE_URL=... CONTENT_TEST_BASE_URL=... NODE_TEST_CLUSTER_SECRET=... npm --prefix web run test:target-leases`。仅允许本地独立 `_test` 数据库。

模拟 Worker 验证协议和控制端状态流转，不代表真实 VPS 的 Docker 回收验收。
