# 单文件 Markdown 教程与后台管理实施计划

状态：解析、本地导入和手动 GitHub 同步闭环已实现，Git 管理模块使用新的后台页面。本文替代原先“模块目录 + 章节文件 + YAML + 镜像构建”的方案。生产解析器位于 `web/server/content/`，可通过 `content:check` 校验；作者说明与模板位于 `docs/content-template/`。使用与部署步骤见 [手动同步说明](git-content-sync-usage.md)。永久删除确认、SEO 与旧编辑器最终移除仍为后续迭代。

## 1. 已确认的内容约定

一个 Markdown 文件就是一个模块。模块名取文件名，章节名取文档的一级标题，章节顺序取一级标题出现顺序。作者不填写模块、章节、题目 ID；数据库 UUID 与访问 slug 由服务端生成并持久化。

```text
content-repository/
  Linux 基础.md
  Web 安全入门.md
  images/
    terminal.webp
```

MD 开头用 YAML frontmatter 配置模块信息，后面直接写教程。代码块内的 `#` 不作为章节；二级及以下标题属于章节内部结构。首个一级标题之前除空白外不允许有正文，避免遗漏内容。

```md
---
summary: 从命令行开始理解 Linux
description: 模块详细介绍，可使用 Markdown。
category: linux
difficulty: beginner
access: authenticated
learningOutcomes:
  - 使用命令查看用户与目录
chapters:
  认识 Shell:
    access: public
    durationMinutes: 15
---

# 认识 Shell

这里是第一章正文。

# 文件权限

这里是第二章正文。
```

- `summary`、`description`、`learningOutcomes` 对齐当前后台和数据库含义，不从正文猜测。
- 分类可选，留空为未分类；难度默认 beginner；章节权限默认 authenticated。
- 顶层 access 是模块内章节的默认权限，不代表新建一种模块级访问制度。
- `chapters` 是可选的按一级标题命名的章节配置，仅在需要覆盖权限或填写预计时长时出现；未匹配的配置报错。模块标题与章节标题不用在配置中重复填写。
- 作者只写使用到的字段；未知字段、重复 YAML 键、不合法枚举、重复章节标题明确报错。
- 标题改名时需要同步更新对应的可选章节配置。
- 第一阶段只识别约定内容目录下的模块 MD，忽略 README.md、图片目录和仓库文档目录；不根据任意 MD 自动创建模块。

练习使用普通围栏代码块，语言标记为 `quiz`，内容为 YAML。示例文件已经包含三道题。字段为 prompt、answer，以及可选 normalization、errorHint。默认 normalization 为 trim，取值复用当前 exact / trim / trim_casefold。

解析器先提取题目，再渲染剩余正文。标准答案和错误提示的原始配置不得进入学员正文、SSR HTML 或页面 payload；判题继续复用当前服务端实现。后台可预览题目和配置，但不再编辑。普通 bash、text 等代码块保持正文用途。

## 2. Git 与后台各管什么

Git 是教程内容的唯一编辑入口。后台负责运营与运行配置，不另存一份可编辑的教程副本。

| 现有功能 | 处理 | 说明 |
| --- | --- | --- |
| 模块列表、搜索、分类/难度/发布状态筛选 | 保留 | 显示来源文件、最近应用提交及内容更新时间 |
| 新建模块 | 替换 | 提供下载 MD 模板和导入说明，真正创建发生在确认同步时 |
| 标题、摘要、详情、目标编辑 | 移除编辑 | 从 Git 解析，只读预览 |
| Markdown 编辑器、正文保存 | 移除 | 不保留与 Git 并行的保存入口 |
| 新增、删除、拖动排序章节 | 移除编辑 | 文件内一级标题和顺序决定，后台只读目录 |
| 章节权限、时长编辑 | 移除编辑 | 由文档头配置，后台只读展示 |
| 题目、答案、归一化规则编辑 | 移除编辑 | 由 quiz 块提供，服务端仍负责判题 |
| 保存为草稿、保存并发布 | 替换 | 内容页变为同步与预览，发布状态单独控制 |
| 发布、下架 | 保留 | 新模块默认未发布；同步不改变已有发布状态 |
| 分类字典增删改查 | 保留 | MD 引用分类 slug，未知分类报错；删除分类仍按当前规则使模块未分类 |
| 模块和章节靶机关联 | 保留后台配置 | 不在教程文件中要求填写数据库模板 UUID；同步不覆盖关联 |
| 前置学习模块推荐 | 保留后台配置 | 第一阶段不扩展 Git 字段；作为独立设置，不混进正文编辑器 |
| 靶机模板、镜像准备、实例管理 | 保留原管理入口 | 不加入教程同步事务，不自动 pull/build，不受正文更新触发 |
| 学习路线编排 | 保留 | 路线是多个模块的集合，与单个 MD 的章节目录分开 |
| 学员进度、完成统计 | 保留 | Git 同步不能重置这些运行数据 |
| 删除模块 | 收敛 | Git 仍存在的文件不能直接在后台删除，否则下次同步会重建；文件移除后先提示下架，永久删除使用独立影响确认 |

类别字典、前置推荐、靶机关联和发布状态仍存于平台数据库。因此内容仓库可以恢复教程本身，不是整个网站与运行配置的完整备份。上述保留字段如果以后需要仓库托管，再显式迁移维护边界，不能两边同时覆盖。

第一阶段只配置一个 GitHub 私有仓库和一个教程目录，不建设通用“内容源中心”。管理员在后台填写仓库、分支、内容目录及只读凭据；凭据由服务端安全保存，不要求作者把教程预先复制到 VPS。具体配置和手动拉取流程见下节。

## 3. 后台页面结构与交互

### 模块列表

沿用现有列表布局，顶部主操作改为“检查 Git 更新”，旁边提供“下载教程模板”。默认不轮询、不自动拉取、不自动导入。

列表展示模块名、发布状态、章节数、分类与难度、来源文件及最近同步时间。行操作为查看详情、前台预览、发布/下架；不保留内容编辑按钮。筛选中的“草稿”改为“未发布”，避免暗示存在可编辑的草稿副本。

### 模块详情

保留一个详情页，用三个清晰的区域组织：

1. 内容预览：模块介绍、目标、章节目录、正文和练习，均只读。标明来源文件和应用的 Commit，提供前往 GitHub 文件的链接。
2. 运行配置：模块默认靶机、章节继承/禁用/覆盖、前置模块推荐。保存按钮明确为“保存运行配置”，不同时更新内容或发布状态。
3. 发布管理：发布/下架、当前状态、校验问题和缺失来源提示。

同步记录只展示最近结果、提交、执行人、时间和错误定位，不建设正文历史版本、版本切换或回滚副本系统；正文历史由 Git 管理。

### 手动同步

点击检查 → 拉取确定的 Commit → 校验与差异预览 → 确认同步。

预览显示新增、更新、文件移除、需要确认的关联及受影响记录数量；选择模块可以查看渲染效果。确认前固定 Commit，不能在确认时悄悄切换到新的分支 HEAD。

第一版整体确认整个有效变更集，不引入按文件分批发布和多个草稿版本。新模块同步后未发布；已发布模块同步后立即更新线上内容，因此确认按钮旁必须明确说明影响。

任务由明确操作触发，通过请求响应更新界面；不添加固定间隔自动查询。网络中断时不得把“未收到响应”当成同步失败或成功，管理员手动查询最后结果。

### GitHub 私有仓库配置与手动拉取（已确认加入计划）

“本地导入”是服务端从一个已经准备好的目录中解析和更新数据库的内部能力，不要求管理员日常登录 VPS 上传文件。实际后台使用流程为：GitHub 私有仓库 → 手动拉取指定目录 → 服务端本地校验/差异预览 → 管理员确认导入。

在学习模块页提供单一“仓库设置”入口，第一版配置：

| 配置 | 说明 |
| --- | --- |
| 仓库 | GitHub 的 owner/repository 或标准 HTTPS 仓库链接；不接收任意下载地址 |
| 分支 | 例如 main |
| 教程目录 | 仓库根目录或如 tutorials；教程 MD 直接位于该目录，图片放在其内部资源目录 |
| 只读凭据 | 推荐 fine-grained Personal Access Token，只授权这个私有仓库的 Contents: Read-only；所需 Metadata 读取权限遵循 GitHub 默认权限 |

这里的“GitHub key”第一版明确为仓库访问 Token，不是 OpenAI key、用户登录用 GitHub OAuth secret，也不是靶机镜像仓库凭据。暂不同时实现 PAT、SSH Deploy Key 和 GitHub App 三套认证。

保存设置只保存配置，不自动测试连接或拉取。提供显式“测试连接”和“拉取并预览”操作，确认导入是单独的数据库写入动作。修改教程目录只改变读取范围，不能被当成已导入内容的批量删除授权。

凭据处理：

- 仅管理员通过 HTTPS 提交；填写框仅用于首次设置和替换，接口读取只返回“已配置/未配置”，不返回 Token、密文或可还原的占位文本。
- Token 使用独立的服务端环境密钥加密后存储；环境密钥缺失时拒绝保存，不明文降级。该密钥通过部署环境提供，不由此后台页面设置。
- 空白凭据表示保持原值；清除凭据使用独立明确操作。Token 不能写进仓库 URL、命令行参数、客户端状态持久化、日志或同步预览。
- 凭据仅用于服务端访问指定 GitHub 仓库，不能传到 Worker 或学员浏览器；错误响应只输出可操作的脱敏原因，如权限不足、仓库/分支/目录不存在、访问失败。

拉取与导入：

1. 管理员点击“拉取并预览”，服务端把分支解析为固定 Commit SHA。
2. 获取该提交指定目录的文件，准备独立本地临时快照；不检出后执行仓库脚本、不安装仓库依赖、不构建 Docker。
3. 调用同一个本地解析/校验服务，生成差异与内容预览；此时不改线上模块。
4. 管理员确认后，将同一提交的有效变更事务写入数据库。不能在确认时切到新的 HEAD；配置或基线已变化则要求重新预览。
5. 成功后更新最近应用提交和结果，失败保留现有内容。临时拉取目录可清理，已发布内容及资源不依赖该目录持续存在。

没有自动定时拉取、Webhook、提交后自动发布、页面自动轮询、启动服务时自动拉取。任务只由明确点击触发并返回结果；若长任务因网络中断未收到响应，管理员手动查询最近操作结果，不能自动重试导入并猜测成功。

GitHub 目录是否存在、访问权限和引用图片范围在拉取阶段验证；模块正文、章节、题目和资源校验仍由统一本地导入服务完成，不建设两套导入逻辑。第一次配置后可手动测试，再拉取示例 MD 验证整个流程。

## 4. 不让作者填写 ID，服务端如何保留进度

- 初次导入生成模块 UUID、稳定访问 slug、章节 UUID、题目 UUID，保存来源关联。
- 模块匹配：仓库内相对文件路径。文件名用于显示名，URL 不在每次改名时重新生成。
- 章节匹配：所属模块 + 一级标题；章节排序按本次文档重排，不按位置匹配身份。
- 题目匹配：所属章节 + 规范化题干；答案、提示和题目位置不是身份。重复题干第一阶段拒绝并定位，避免错误合并。
- 相同来源再次导入复用原记录；正文、答案、预计时长、顺序变化原地更新。沿用当前完成记录保留规则，不要求学员因内容更新自动重做。
- 文件、章节标题、题干改名会出现“原记录消失/新记录出现”，预览允许管理员确认它们是同一个对象。系统保留原 UUID、URL 和完成记录。
- 相似度或 Git rename 信息最多作为建议，不能据此自动覆盖身份；关联必须一对一。管理员拒绝关联则按真实新增/移除处理并明确说明影响。
- 不通过全文哈希重新生成身份；文件哈希只用于发现内容变化。

永久删除与已有表的级联删除规则涉及进度损失，不能在普通同步中隐式执行。第一版源文件移除只展示提示与下架入口；文档内章节/题目移除、无法确认的改名先阻断该次同步并给出影响信息。删除确认能力随后单独迭代，不做静默忽略或半份同步。

## 5. 服务端实施边界

### 解析层

使用 Markdown 语法树提取一级标题和顶层 quiz 围栏，YAML 解析文档头与题目字段，输出内部 ModuleInput 对应的规范数据和源文件/行号信息。生产解析器不能直接照搬原型 generate.mjs。

复用当前字段校验、答案规范化/判题、访问控制、章节排序和发布检查。现有 content.ts 的“全量保存时删除未提交章节/题目”不能直接用作 Git 导入删除策略；应提取共享验证与写入能力，由同步服务提供已经确认的 UUID 映射和明确更新集合。

### 来源及同步状态

使用一个来源关联表记录模块/章节/题目的数据库 ID、来源路径/标题/题干匹配键；唯一约束避免重复导入。记录的是身份映射，不保存正文版本副本。

单个同步状态记录最近应用的 Commit、内容摘要、执行人、完成时间及结果。模块详情保留最近应用提交信息。后台读取同步摘要不包含原始标准答案、Token 或仓库凭据。

### 同步提交

每次操作使用独立临时目录，拉取并解析指定 Commit，准备图片后再进入短数据库事务。确认阶段重新检查来源基线、引用有效性和 lockVersion；并发同步或后台配置冲突需要重新检查，不静默覆盖。

事务内更新来源映射、模块、章节、题目与资源引用，保持原 UUID，原子提交。发布状态和运行配置保留数据库当前值，不被预览中的旧值覆盖。内容版本号正确递增，后台运行配置保存也必须受版本检查保护。

不在数据库事务中执行 git、网络下载、Docker 操作；不增加消息队列、Webhook、自动同步调度器或网站正文历史版本系统。旧 Commit 的恢复通过明确选择提交并再次预览同步完成，仍遵守关联和删除规则。

### 图片与权限

相对路径以 MD 文件位置解析，校验最终路径留在允许的仓库资源目录内，不机械禁止所有 `..`。拒绝越界路径、符号链接和不存在的资源，并限制大小与允许格式。

图片复制为内容哈希命名的本地资源，复用 assets/章节资源关联；先准备文件再引用，不覆盖线上旧文件。数据库事务失败允许留下未引用文件，后续显式清理，不承诺跨文件系统事务回滚。

封面等明确公开资源可以公开缓存。受限正文配图必须通过检查所属章节权限的资源路由提供，不能把所有私有课程图片都暴露到无鉴权的 Nginx 静态目录。共享资源只要经任一允许访问的章节可读，不因此暴露其他章节的正文或答案。

## 6. 分轮实施与验收

### 第一轮：生产解析器和规范模板

把已确认的单 MD 格式固化为可复用解析器、示例及作者说明。支持模块头、章节、quiz、可选章节配置、图片引用发现，暂不写线上数据库。

验收：代码块中的 `#`、嵌套标题、普通代码、表格和图片正确处理；非法头、重复标题/题干、空答案和越界图片都有文件/行号错误；答案不出现在学员输出中。原型不参与正式部署。

### 第二轮：本地导入闭环

新增来源映射、同步状态和资源支持，先从指定本地目录手动导入。实现差异计算、明确的改名关联确认、事务更新、保留进度和发布状态。

验收：首次导入、重复导入不重复创建；正文/排序/答案修改不丢原记录；改名确认后 UUID 不变；不确认改名或出现移除时不写库；任一校验/事务失败原线上数据不变；正文和配图权限一致。

### 第三轮：Git 手动检查与确认同步

实现后台仓库设置：仓库、分支、教程目录、只读 Token 的安全保存与替换。提供手动测试连接、拉取并预览、确认导入接口，复用第二轮的本地导入服务，展示固定 Commit 与差异；没有后台定时拉取或前端轮询。

验收：使用真实私有测试仓库的只读 Token 成功访问选定目录，目录外的 MD 不导入；缺少权限、错误分支或目录明确报错；保存配置/刷新页面不会拉取；检查和确认间远程出现新提交仍应用原先确认的 Commit；重复点击/并发同步不会重复创建；仓库不可达不影响学员阅读；读取配置与日志不包含 Token 或标准答案。

### 第四轮：后台界面收敛并切换维护方式

按功能表改造模块列表与详情，移除旧 Markdown 编辑、章节和题目编辑、旧保存/创建入口；后端同时拒绝 Git 管理字段的网页写入，保留独立的运营与运行配置接口。

现有网页创建的模块由管理员明确关联到仓库文件，不能仅凭同名自动覆盖。关联后再切换为 Git 管理；过渡期间未关联的旧模块保持原模式，全部接管后清理旧编辑组件与不适用接口，避免长期维护两套编辑系统。

验收：后台可预览、发布/下架、保存靶机关联；无法通过旧 API 修改 Git 内容；同步不覆盖运行配置；分类和路线管理继续正常工作。此轮不做新样式切换或新的管理端布局系统。

### 第五轮：删除确认与公开内容 SEO

增加来源移除后的独立删除影响确认；完成 SSR 标题、描述、Canonical 与动态 Sitemap。公开正文和受限正文继续使用既有权限规则，不为了预渲染暴露受限正文或图片。

CI 校验在第一轮解析器稳定后即可接入内容仓库，不必等待后台全部完成；CI 不负责自动发布。

## 7. 当前实施顺序

解析器、本地导入、身份映射、GitHub 后台配置与手动拉取，以及 Git 管理模块的新详情页已落地。当前保留隔离的旧编辑器仅供未接管模块过渡；永久删除确认、SEO 和旧编辑器最终移除留待后续。下一步先用实际私有教程仓库验证作者工作流，不同时增加自动同步、靶机或论坛功能。
