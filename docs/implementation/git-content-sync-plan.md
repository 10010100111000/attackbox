# Git 内容与靶机同步方案

将私有 Git 仓库作为教程模块、章节正文、教程图片、测验题目与答案、靶机模板定义的唯一数据源（Single Source of Truth）。VPS 通过只读 Deploy Key 拉取内容仓库，经离线校验、差异预览与管理员确认后，完成靶机 Docker 镜像预热（`docker pull` 或本地 `docker build`）、图片静态化落盘，并在单事务内同步至 PostgreSQL。学员访问全程只读本地数据库与本地静态文件，不经过 GitHub。

---

## 一、 职责与数据边界

避免 Git 与后台双写冲突，明确划分维护位置：

| 内容类别 | 唯一维护位置 | 运行时存储位置 | 后台界面行为 |
| :--- | :--- | :--- | :--- |
| **模块介绍、章节目录、Markdown 正文、教程图片** | Git 私有仓库 | PostgreSQL + 本地静态目录 | 只读展示来源与渲染预览，移除编辑输入框 |
| **章节测验题目、标准答案、错误提示** | Git 私有仓库 | PostgreSQL（答案转为 `answer_hmac` 存储） | 只读展示题目列表与提示，不明文回显答案 |
| **靶机模板定义、开放端口、访问说明、构建脚本** | Git 私有仓库 | PostgreSQL (`target_templates`) + 本地 Docker 镜像库 | 只读展示模板配置、镜像就绪状态与课程绑定关系 |
| **分类字典（Category）** | 网站后台 / 仓库配置 | PostgreSQL (`content_categories`) | 按稳定标识（`slug`）匹配，不根据显示名称自动创建重复分类 |
| **模块上架 / 下架、靶机模板启用 / 停用** | 网站后台 | PostgreSQL (`modules.status` / `target_templates.enabled`) | 保留运营开关，操作立即生效，不等待修改 Git |
| **用户、完成记录、学习进度、运行中靶机实例** | 线上运行时产生 | PostgreSQL (`chapter_progress` / `question_completions` 等) | 按稳定标识关联，后台只读查看 |

## 二、 内容仓库结构与核心约定

### 1. 目录结构

单独建立私有内容仓库，约定固定目录层级：

- `targets/<target-id>/`
  - `target.yml`：靶机元数据、端口列表、访问说明，以及镜像获取方式（远程镜像地址或本地构建）。
  - `Dockerfile` 及环境源码（可选）：当采用仓库内自建模式时，存放靶机构建文件与启动脚本。
- `modules/<module-id>/`
  - `module.yml`：描述模块信息、默认靶机标识、前置模块标识列表，以及有序章节目录、各章节测验题目与标准答案。
  - `chapters/*.md`：纯章节正文 Markdown。
  - `images/*`：模块封面与章节插图。

### 2. 核心约定

1. **稳定标识映射**：
   - 模块 `id` 映射数据库 `modules.slug`；
   - 章节 `id` 映射数据库 `chapters.slug`；
   - 靶机 `id` 映射靶机模板唯一标识；
   - 分类 `category` 映射数据库 `content_categories.slug`。
   - 只要 `id` 不变，修改标题、调整章节顺序、移动 `.md` 文件路径均在原数据库记录上原地更新（保持主键 UUID 不变），不会重置学员进度与答题记录。
2. **枚举与规则对齐**：
   - 模块难度（`beginner` / `intermediate` / `advanced`）、章节权限（`public` / `authenticated`）、答案归一化方式（`exact` / `trim` / `trim_casefold`）、端口协议（`tcp` / `udp`）严格匹配当前后端校验规则。
3. **靶机双重供给模式**：
   - **远程镜像模式（Pull）**：在 `target.yml` 中声明带明确 tag 或 `@sha256` digest 的镜像地址，同步时由服务器提前拉取。
   - **仓库构建模式（Build）**：在 `targets/<target-id>/` 下提供 `Dockerfile` 与靶机文件，同步时由服务器根据目录内容哈希在本地构建为 `attackbox-target/<target-id>:<content-hash>` 镜像并写入模板表，无需依赖外部镜像仓库。
4. **图片相对路径**：
   - Markdown 内仅允许引用模块 `images/` 目录下的相对路径图片，禁止外链图片、路径穿越（`..`）与原始可执行脚本标签。

## 三、 同步、预热与发布流程

后台新增统一的仓库同步入口，遵循五步流转：

1. **选择提交并拉取**
   - 服务端使用只读 Deploy Key 在独立工作目录 `/var/lib/attackbox/content-repo` 拉取指定分支或 Commit，展示提交历史与当前线上已发布的 Commit SHA。
2. **离线校验**
   - 校验所有 `target.yml`、`module.yml` 格式、必填项、唯一 ID、枚举范围；
   - 校验章节 `.md` 文件与相对路径图片是否真实存在；
   - 校验模块引用的 `category` 标识在数据库中是否存在，引用的 `target` 与前置模块是否存在且未形成循环依赖。
   - 任何一项未通过则直接阻断发布，线上数据保持不变。
3. **查看差异与删除确认**
   - 对比目标 Commit 与当前 PostgreSQL 数据，清晰列出**新增、修改、待移除**的靶机模板、模块、章节和测验题目。
   - 若存在待移除的模块或章节，统计并显示受影响的学员进度条数与答题记录数。删除操作不因文件缺失自动执行，必须由管理员显式勾选确认后才放行。
4. **资源准备与靶机镜像预热（先于正文发布）**
   - **图片准备**：计算仓库图片 SHA-256，复制到 `/var/lib/attackbox/content-assets/`，并将待入库正文中的相对路径转换为站内静态路径 `/content-assets/...`。
   - **靶机预热**：对本次新增或变更的靶机模板，在发布前于节点本地执行 `docker pull`（远程镜像模式）或 `docker build`（仓库构建模式），确认本地 Docker 守护进程中镜像已就绪。消除原本“首个学员点击启动时才拉取镜像导致 120 秒锁阻塞与超时”的问题。
5. **单事务写入数据库**
   - 获取 `pg_advisory_xact_lock` 全局内容锁，在单个 PostgreSQL 事务中依次更新靶机模板、模块、章节（复用偏移量策略重排 `position`）与测验题目（答案经 HMAC 计算后存入 `answer_hmac`）。
   - 新增模块默认保持 `unpublished` 状态；已存在模块保留后台当前的 `status` 上架状态，不被同步重置。
   - 事务失败则整体回滚，保留当前线上可用内容。

## 四、 公开页面 SSR、SEO 与缓存边界

1. **完整服务端 HTML 与元信息**
   - 模块介绍页、目录与 `access: public` 的公开章节直接通过 Nuxt SSR 返回完整服务端 HTML。
   - 每个页面输出独立的 `<title>`、摘要 `<meta name="description">` 和规范地址 `<link rel="canonical">`。
2. **受限章节防泄露**
   - 对 `access: authenticated` 的登录章节，未登录请求在服务端鉴权阶段即拦截，不查询、不下发 `bodyMarkdown` 与题目详情，确保公开 HTML 与 `__NUXT_DATA__` 页面数据中均不包含受限正文。
3. **动态 Sitemap**
   - 新增 `/sitemap.xml` 服务端路由，仅输出 `status = 'published'` 的模块及 `access = 'public'` 的章节地址。
   - 后台执行模块下架或同步修改章节访问权限后，`/sitemap.xml` 与页面访问控制立即同步生效。

## 五、 分步实施顺序与验证方案

### 阶段 1：仓库规范与独立校验器

- **实施内容**：
  1. 确定 `target.yml` 与 `module.yml` 字段规范；
  2. 编写独立校验器（供本地命令行、后台同步、GitHub Actions 共用），覆盖语法、唯一 ID、枚举值、相对路径图片存在性、Markdown 安全过滤；
  3. 编写 1 个包含靶机定义、章节正文、配图与测验题目的示例模块（`linux-basics`）。
- **验证方式**：
  - 对标准示例模块运行校验器，验证零错误通过；
  - 构造缺失图片、重复章节 ID、非法难度枚举、含 `../` 路径穿越、空答案等错误样本，验证校验器全部准确拦截并给出具体文件与字段定位，全程不写线上数据库。

### 阶段 2：图片静态托管与靶机镜像预热

- **实施内容**：
  1. 配置 `/var/lib/attackbox/content-assets/` 静态目录与 Nginx `/content-assets/` 路由（开启长缓存）；
  2. 实现图片按内容哈希复制与 Markdown 图片相对路径重写；
  3. 实现靶机模板的远程镜像预拉取（`docker pull`）与仓库内 `Dockerfile` 本地构建（`docker build`），确认镜像在本地 Docker 就绪后再登记模板。
- **验证方式**：
  - 分别准备 1 个远程镜像靶机和 1 个带 `Dockerfile` 的自建靶机执行预热，通过 `docker image inspect` 验证镜像已在本地生成；
  - 学员端点击启动靶机，验证容器在 1–2 秒内直接进入运行态，无拉取等待；
  - 浏览器打开含图片的章节，通过 Network 面板验证图片从本站 `/content-assets/...` 加载且返回 200，无任何 GitHub 域名请求。

### 阶段 3：后台同步流水线与差异预览

- **实施内容**：
  1. 实现后台同步页面与接口（拉取提交 → 执行校验 → 生成模块/章节/题目/靶机差异报告 → 确认发布）；
  2. 实现单事务按稳定 ID（`slug`）增量更新模块、章节、题目与靶机绑定；
  3. 对缺失模块/章节增加单独的删除确认开关与影响范围提示。
- **验证方式**：
  - **首次同步验证**：空库同步示例仓库，验证靶机模板、模块、章节、题目正确入库，答案以 HMAC 存储且前端可正常判题。
  - **进度保留验证**：用测试账号完成第 1 章学习与答题；随后在 Git 中修改第 1 章标题、移动 `.md` 文件位置、调整章节顺序并修改第 2 章正文，再次同步。验证测试账号在第 1 章的完成进度与答题通过状态完好保留。
  - **异常回滚验证**：构造未知分类或损坏镜像导致同步中途失败，验证线上已有课程、图片和进度不受任何影响。
  - **删除保护验证**：在 Git 中移除某章节，验证未勾选删除确认时拒绝执行删除；勾选确认后章节及其关联记录被级联清理。

### 阶段 4：后台编辑边界收敛

- **实施内容**：
  1. 后台模块详情页与靶机模板页将 Git 托管字段（标题、摘要、目录、正文、题目、镜像、端口等）改为只读预览，显示数据来源与最近同步的 Commit SHA；
  2. 保留模块“发布 / 下架”开关、靶机模板“启用 / 停用”开关；
  3. 收敛后端保存接口，拒绝直接修改由 Git 托管的内容字段。
- **验证方式**：
  - 登录后台查看模块与靶机详情，确认正文、目录、题目、端口等处于只读预览状态，无重复编辑入口；
  - 点击模块“下架”与“发布”，验证学员端可见性立即切换，且再次执行 Git 同步不会冲掉已发布状态。

### 阶段 5：公开页面 SEO 与 CI 完善

- **实施内容**：
  1. 为模块页、公开章节页补齐 SSR 独立标题、摘要、规范地址（Canonical URL）；
  2. 实现 `/sitemap.xml` 动态生成，并细分公开页与登录页的 `Cache-Control` 策略；
  3. 在内容仓库接入 GitHub Actions，对每次 PR 自动运行阶段 1 的校验器。
- **验证方式**：
  - 使用不带 Cookie 的 `curl` 访问公开章节，验证返回 HTML 直接包含完整正文、独立 `<title>`、`<meta name="description">` 与 `<link rel="canonical">`；
  - 使用不带 Cookie 的 `curl` 访问 `authenticated` 登录章节，验证返回 HTML 与 `__NUXT_DATA__` 中均不含受限正文；
  - 访问 `/sitemap.xml`，验证仅包含已发布模块和公开章节，后台下架模块后立即从 Sitemap 中消失；
  - 在内容仓库提交含格式错误的 PR，验证 GitHub Actions 自动拦截。
