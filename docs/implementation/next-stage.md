# 下一阶段实施计划

更新日期：2026-10-23。本文描述后续工作，未标记为完成的能力均尚未实现。

## 当前基线

已经实现管理员单份内容编辑、保存为草稿时下架、保存并发布、分类、前置模块建议、章节时长与测验配置。标准答案支持管理员回显和直接修改；公开接口不返回答案原文或摘要。

章节学习页已按确认的概念稿调整：可收起目录、宽版正文、等宽练习、单一返回入口和 CLI/GUI 面板入口。面板支持调整高度、展开、收起、关闭，目前显示真实的不可用状态，尚未连接 Worker。

以下能力仍然缺失：服务端学习完成记录、顺序解锁、继续学习、真实学习统计和新平台的沙箱控制接口。目前“全部通过”只表示当前页面中的答题反馈，刷新后不会成为已保存进度。

本阶段保持现有 Nuxt + PostgreSQL + Drizzle 技术栈与已确认的正文布局，不再新建内容版本系统，不引入会员制度。

## 本次发布

在 `web/` 目录中、使用部署环境已配置的 `DATABASE_URL` 执行：

```bash
npm ci
npm run db:migrate
npm run build
```

随后重启应用。已有当前基线数据库只需执行增量迁移 `0001_editable_question_answers.sql`，无需重置。该迁移仅增加标准答案原文字段；旧摘要不能还原成原文，原有题目可继续判题，管理员补填一次后才能回显和直接调整匹配方式。

已验证：53 项常规测试、数据库迁移与内容生命周期测试、TypeScript 检查、生产构建，以及章节阅读/判题/目录收起/面板交互/移动端/主题的浏览器检查。发布后再对实际环境核对首页、登录、模块保存与章节阅读。

## 交付一：学习进度与权限，优先实施

先补齐服务端能力及集成测试，再接入现有界面。每一步均可单独提交。

### 1. 两张最小进度表

| 表 | 核心字段 | 职责 |
| --- | --- | --- |
| chapter_progress | user_id、chapter_id、started_at、last_visited_at、completed_at | 阅读位置、章节完成状态 |
| question_completions | user_id、question_id、passed_at | 记录当前题目是否已答对 |

分别以用户和章节/题目的组合建立唯一约束。用户、章节、题目删除时清理对应关联；按用户与最近访问时间建立查询索引。沿用稳定的章节、题目 ID。

暂不单独保存模块百分比、用户累计学习时长、错误答案历史或用户画像。模块进度由当前章节和完成记录汇总，避免维护多份状态。

### 2. 完成与解锁规则

- 访客可直接阅读公开章节并尝试答题，不持久化个人进度；登录后按账号保存，不将浏览器状态直接当作完成证明。
- 已激活用户打开可访问章节后更新最近阅读记录；重复访问不修改首次开始时间。
- 有测验的章节：服务端判题正确后，幂等写入该题通过记录；本章当前题目全部答对后，事务内写入章节完成时间。客户端不能提交“已通过”布尔值代替判题。
- 无测验的章节：正文末尾提供“完成本章”，服务端检查登录、发布状态与章节可访问性后写入完成记录。不将打开页面或滚动到底自动算作完成。
- 公开章节继续作为不受顺序锁限制的预览。尚未完成的登录章节要求其前面的章节均已完成；第一章没有前置章节。已完成章节始终可回顾。
- 正文、标准答案和测验更新不自动撤销既有章节完成状态。新增题目不要求已完成用户重做；未完成用户按当前题目清单判定。
- 新增或调整章节顺序保留所有既有完成记录，只重新计算尚未完成章节的解锁条件；删除章节后从模块总数中移除。
- 前置模块仅为学习建议，不加入上述解锁判断。
- 多窗口同时答题、重复请求和管理员同时编辑内容时，通过事务和唯一约束保持幂等；判题、章节完成判断和内容读取必须使用一致的当前章节数据。

### 3. API 契约先行

以下是拟定接口，实施时先统一共享类型和接口文档，再修改页面：

| 接口 | 拟定职责 |
| --- | --- |
| 现有模块目录 GET | 返回明确的 lockReason：login / prerequisite / null，以及当前用户的完成状态 |
| 现有章节 GET 与 attempt POST | 同时执行发布、登录与顺序权限检查；答题响应增加本章完成状态 |
| POST /api/modules/:slug/chapters/:chapterSlug/visit | 记录最近访问，不返回受限正文 |
| POST /api/modules/:slug/chapters/:chapterSlug/complete | 完成无测验章节；有测验时必须检查服务端通过记录 |
| GET /api/me/learning | 返回当前账号的模块进度与最近阅读入口 |

`isLocked` 可继续保留为展示兼容字段，但必须与 `lockReason` 一致。需要登录返回 401，登录后仍未解锁返回 403；下架或删除保持 404。正文 GET、答题 POST、完成与访问记录接口共享访问检查，不能只在目录或按钮上控制。

公开模块介绍和目录保留 SSR；所有携带用户进度或受限正文的响应不得被共享缓存。只读公开接口不返回题目答案、其他用户进度或未发布内容。

### 4. 沿用现有 UI 接入真实状态

- 模块详情：开始学习 / 继续学习 / 回顾模块，以及真实完成数量。
- 学习目录：当前阅读、已完成、可阅读、需先完成前置章节、需登录，采用统一图标和明确文字。
- 正文测验：刷新或重新登录后恢复已通过状态；完成后更新目录和下一章入口。访客不显示虚假的已保存进度。
- 无题章节：仅在这种情况下显示“完成本章”；成功后可进入下一章。
- 学习首页：最近学习卡片使用真实记录；新用户显示正常模块列表，避免空进度占位卡。
- 登录跳转：保留原章节地址；登录成功后重新读取权限和进度。
- 清理学习首页轮播中的固定示例模块链接，使用真实已发布模块；没有对应内容时隐藏入口或显示明确空态。

### 5. 验收

1. 真实账号完成一章后，刷新、退出重登、另一个浏览器中都能恢复进度。
2. 有题、无题章节均能完成；错题、重复提交与多窗口提交不会重复累计。
3. 访客能预览公开章节，不能通过修改地址或直接请求绕过登录和顺序限制。
4. 正文、答案、题目、排序更新后遵循上述保留规则；下架后不能继续读取或答题。
5. SSR 和登录后导航保持一致，不出现短暂展示受限正文或串用其他用户进度。
6. 浏览器端到端验证管理员发布 → 用户阅读 → 答题完成 → 下一章解锁 → 首页继续学习，不用静态字符串检查替代这条流程。

交付一完成前，不同时扩展节点管理、用户画像和学习路线编排。

## 交付二：接入真实沙箱

学习闭环验收后，再为现有 `PracticeDock` 接入真实实例。先完成单节点 CLI 的纵向流程，再接 GUI，最后扩展多节点配置。

1. 对照 [现有沙箱约定](../sandbox/sandbox.md) 列出 Go Control 的调度、用户实例唯一性、Ticket、心跳和回收职责，以及 Nuxt 接管所需的接口与验收用例。保留 Go Worker；新平台以新用户 ID 为准，不要求重新使用旧账号。
2. Nuxt 提供实例状态、幂等启动、释放、访问 Ticket 的服务端接口。签名密钥和节点凭据只留在服务端，浏览器使用短期 Ticket 连接 Worker。
3. 先打通一个真实节点的 CLI：启动 → 连接 PTY → 输入输出 → 短时断网后重新获取 Ticket → 复用仍存活的实例。现有终端会话能否续接按 Worker 的 PTY 能力实测，不能只凭 WebSocket 重连成功宣称恢复。
4. 再接同实例的 GUI/noVNC。顶部切换 CLI/GUI 不创建第二个沙箱；调整、收起和关闭面板不释放实例，主动释放另设明确操作。
5. 展示真实创建中、运行中、断开、已回收和失败状态；统一处理 TTL、Idle 和节点重启后的状态刷新。
6. 新控制接口完成等价验证后再切换部署并移除 Go Control；迁移期间不让两个控制端同时管理同一个节点。

这部分另开实施批次，不在进度改造时同时迁移沙箱调度。
