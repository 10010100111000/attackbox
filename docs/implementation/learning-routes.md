# 学习路线编排

路线由多个模块组成，模块大纲仍由章节组成；路线不复制章节、正文、测验或进度。

## 本轮实现

- `/admin/routes`：路线列表、草稿／发布状态、模块数量、编辑和删除。
- `/admin/routes/new` 与 `/admin/routes/:id`：名称、简介、模块搜索添加、移除和上下排序。新建编辑器不创建数据库记录，首次保存才创建。
- 保存为草稿会下架整条路线，保存并发布一次提交全部内容。发布至少包含一个模块，所有被选模块必须已发布；每条路线最多 100 个不同模块。
- `/learn` 的学习路线标签显示真实路线；`/learn?tab=routes` 可直接进入此标签。
- `/learn/routes/:id`：SSR 路线介绍、模块顺序、真实章节数与已配置时长；登录后根据现有完成记录汇总进度。入口指向第一个未完成模块，全部完成后可回顾。
- 模块间只提供推荐顺序，不增加跨模块强制解锁。模块内沿用原有章节解锁与权限校验。

## 发布与删除边界

公开接口只展示路线内当前已发布的模块，模块下架后不泄露其名称和简介；所有模块均下架时，路线从公开列表隐藏，详情返回 404。再次发布模块后自动恢复，不丢失原编排。草稿路线不出现在公开列表或详情中。

路线删除不删除模块和学习记录。模块如果被任意路线引用，删除返回 409，要求管理员先从路线移除；数据库外键同时保护并发删除。修改模块状态不受此限制。

路线保存通过事务更新信息和模块排序，乐观锁阻止旧页面覆盖新编辑。公开详情使用只读一致性快照。管理员写接口校验管理员身份及请求来源；涉及个人进度的响应与 SSR 路线页禁止共享缓存。

## 数据与部署

新增 `0005_learning_routes.sql`，以及对应 Drizzle snapshot：

- `learning_routes` 保存名称、简介、状态和并发修改标识。
- `learning_route_modules` 保存有序引用，同一路线的模块和位置分别唯一，路线删除级联清理引用，模块删除采用 RESTRICT。

部署新版本前在 `web/` 执行 `npm run db:migrate`，不需要清库。随后生产构建并重启应用。

## 验证

`npm run test:routes` 使用 `CONTENT_TEST_DATABASE_URL` 和 `CONTENT_TEST_BASE_URL` 指向隔离的本机测试库与 Nitro。测试覆盖发布原子性、排序、草稿隔离、未发布模块拒绝、重复模块、个人进度隔离、下架隐藏、删除保护、修改冲突及 Chromium 的新建／排序／发布／阅读流程。不连接远程服务器。增量升级测试通过 `ROUTES_MIGRATION_TEST_DATABASE_URL` 指向另一个全新本机 `_test` 库，先应用旧迁移并写入账号和模块，再升级至 0005，确认既有内容保留。

本轮已通过 80 项常规测试、路线接口与浏览器流程、旧库增量升级、原有内容／学习进度及学习浏览器回归；TypeScript 检查、生产构建和 Drizzle 无差异检查通过。测试服务与数据库仅位于本地临时环境。
