[ATTACKBOX ARCHITECTURE & FLOWS]

1. TOPOLOGY
- Browser SPA: Hosted statically by Nginx, English UI
- Control (:18080): Bound to 127.0.0.1, proxied by Nginx for /api/* only. Holds user DB, Ed25519 key, sandbox scheduler
- Worker (:8443): Bound to 0.0.0.0. Holds signing public key, cgroup, btrfs, pty. Connects reverse WS to Control
- CRITICAL: Terminal/Desktop PTY is direct WebSocket from browser to Worker :8443 with ticket. NO NGINX PROXY

2. AUTH & ONBOARDING FLOW
- Send code: POST /api/auth/send-verification-code (email)
- Register: POST /api/auth/register (email, code, password, optional username)
- Control checks collision, assigns autoincrement ID, defaults to USER_<id>, issues Ed25519 JWT
- Login: POST /api/auth/login strictly requires email + password

3. WORKSPACE & SANDBOX PROVISIONING
- Workspace default state: STANDBY
- Launch: User clicks TERMINAL or DESKTOP -> POST /api/sandbox/start
- Control allocates slot IP, dispatches RPC to Worker to setup cgroup/veth/snapshot, issues 60s ticket (ptk_...)
- Browser opens new tab (/term or /gui), connects directly to ws://<worker_ip>:8443/ws/cli?ticket=...
- Worker verifies ticket signature, binds pty session
- Workspace HUD transitions to ACTIVE, begins lease countdown

4. MULTI-TERMINAL CLI FLOW
- CliView.vue runs WinBox virtual window manager
- Users can open, minimize, and tile multiple independent terminal windows in one tab
- Each window requests ticket and opens independent direct WebSocket PTY connection to Worker

5. TEARDOWN & LIFECYCLE
- Trigger 1: User clicks RELEASE button -> POST /api/sandbox/stop
- Trigger 2: Max lease TTL (120 minutes)
- Trigger 3: Idle timeout (10 minutes with no keyboard input on PTY)
- Worker stops init process, unmounts snapshot, releases veth, notifies Control to free slot
- Workspace HUD resets to STANDBY
