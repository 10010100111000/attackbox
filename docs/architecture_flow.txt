[ATTACKBOX ARCHITECTURE & FLOWS]

1. Browser -> Nginx static SPA and /api/* -> Control (:18080).
   Browser terminal/desktop WebSockets connect directly to Worker (:8443).
   Configure TLS/public_data_url for HTTPS deployments.

2. One running sandbox per authenticated user.
   CLI and GUI pages both POST /api/sandbox/start to create or reuse it.
   Concurrent creation waits for the existing sandbox; cleanup never allocates another one.
   Worker owns actual resources and lifecycle; Control owns authentication/scheduling.

3. TERMINAL opens/focuses the named CLI page without reloading it.
   The page contains multiple PTYs in the same sandbox, running as box.
   CLI alone never starts TigerVNC or MATE.

4. DESKTOP opens/focuses the named GUI page.
   Worker lazily ensures TigerVNC + MATE in the same sandbox, then forwards VNC.
   The desktop runs as box, sharing home/files/network/cgroup with CLI.
   VNC listens on a Unix socket only; no independent desktop sandbox is created.

5. Closing a terminal ends its PTY. Closing GUI only disconnects the viewer.
   GUI reconnect fetches a new ticket and reuses a surviving desktop.
   Reconnect does not recreate a sandbox which has already been released.
   No independent desktop stop control is provided.

6. RELEASE, configured TTL, or configured idle timeout destroy the whole sandbox.
   Keyboard/mouse input renews activity; display refresh/handshake/keepalive do not.
   Worker PID 1/cgroup teardown includes all desktop and terminal processes.
   Control releases user/slot after cleanup confirmation.
   Workspace refreshes status periodically and on window focus.

7. Worker/Control restart semantics and security boundaries are in ARCHITECTURE.md.
   Ordinary connection loss does not have the same semantics as daemon restart.
