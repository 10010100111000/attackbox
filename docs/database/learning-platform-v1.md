# AttackBox 数据模型

当前版本面向全新数据库。内容直接编辑，通过“保存为草稿 / 保存并发布”一次确定内容与公开状态；不提供历史版本、草稿副本或回滚功能。

## 已实现的数据表

| 表 | 用途 |
| --- | --- |
| users | 账号、密码摘要、角色、状态、邮箱验证 |
| auth_sessions | 登录会话，保存令牌摘要 |
| email_tokens | 邮箱验证与找回密码令牌 |
| audit_logs | 操作人、动作、目标及时间，不保存正文历史 |
| content_categories | 内容方向分类，与学习难度独立 |
| modules | 模块元信息、公开状态、并发修改计数 |
| chapters | 模块的有序章节、Markdown 正文、访问权限和预计时长 |
| module_prerequisites | 模块之间的有序前置学习建议 |
| chapter_questions | 章节题目、判题规则、可编辑标准答案及判题 HMAC |
| assets | 文件存储索引与资源属性 |
| chapter_assets | 章节与附件的关联 |
| chapter_progress | 用户的章节开始、最近访问和完成时间 |
| question_completions | 用户已答对的稳定题目 ID |

## 模块

`modules` 直接保存 `title`、`slug`、`summary`、`description_markdown`、`difficulty`、`category_id`、`cover_asset_id`、`learning_outcomes`。学习目标为可选文本数组，后台逐行编辑，最多 12 项、每项 200 字；未填写时前台不显示对应区域。

- `status` 只有 `unpublished` 和 `published`。下架回到 `unpublished`，内容不变。
- `lock_version` 从 1 开始，每次修改或发布状态变更递增，用于阻止过期页面覆盖内容。它不是内容历史版本。
- `created_by`、`created_at`、`updated_at` 记录创建与更新时间。
- `published_at` 记录首次发布时刻，下架不清除。
- `slug` 全局唯一，创建后不可修改。
- 删除模块时真实删除其章节、题目和附件关联；附件文件本身不连带删除。

默认提供 Web 安全、Linux 基础、网络安全、云原生安全、逆向分析、容器安全六种分类。管理员可添加分类。未指定分类显示“未分类”。难度为 `beginner`、`intermediate`、`advanced`。

## 章节和题目

`chapters` 直接属于模块，保存 `position`、`title`、`slug`、`access`、`body_markdown`、`duration_minutes`。时长为可选的 1–1440 分钟整数，空值不展示；只有所有章节都填写时才汇总预计总时长。模块内访问标识与位置分别唯一，位置为正整数。

`chapter_questions` 直接属于章节，保存稳定的 `id`、`position`、`prompt_markdown`、`error_hint`、`normalization`、`answer`、`answer_hmac`、`answer_key_version`。

- 普通编辑与排序保留章节和题目 ID，不复制记录。
- 新建题目产生新 ID；删除题目真实删除记录。
- 标准答案原文仅通过管理员详情接口返回，编辑器直接回显、修改。发送空字符串清空答案；省略字段保留原值。判题 HMAC 随答案或匹配方式自动更新，不保存历史答案。旧题仅有 HMAC 时仍可判题，补填一次后支持回显。
- 规则支持 `exact`、`trim`、`trim_casefold`。已有答案原文时，更改规则会自动重新计算判题摘要，无需重填。
- 公开接口通过字段白名单返回数据，不返回答案原文、摘要或内部管理字段。

## 公开与鉴权

模块介绍和目录在模块发布后公开。`public` 章节直接可读；`authenticated` 章节要求有效且已激活的账号。鉴权在正文及答题接口执行。

学习进度关联稳定的章节与题目 ID。公开章节不受顺序锁限制；未完成的登录章节要求所有前面的章节均已完成，已完成章节始终可以回顾。所有正文、答题、访问和完成接口执行相同规则。

有题章节通过全部当前题目后自动完成；无题章节由已登录用户明确完成。通过记录以用户与题目组合唯一，完成时间首次写入后保留。正文、答案、题目和排序变化不自动撤销完成记录，新增题目只影响尚未完成章节。删除章节、题目或账号时级联清理对应记录。

进度写事务先锁定模块行（FOR SHARE，内容编辑持有同一模块的 FOR UPDATE），再取得按用户/模块划分的事务 advisory 锁，以串行处理并发答题和完成判断。模块进度从当前章节实时汇总；最近学习只查询已发布模块，不保存额外模块计数和错误答案历史。

进度与受限正文返回 `Cache-Control: private, no-store` 并按 Cookie 区分响应。账号切换会清理 Nuxt 中的学习数据缓存。

## 保存与发布

- 新建页只维护本地表单，首次保存才创建模块，初始为未发布。
- 保存包含整个模块、章节清单、题目和顺序，在一个事务内完成。
- “保存为草稿”保存内容并设为未发布；已发布模块会同时下架，编辑器先提示。
- “保存并发布”在同一事务中保存内容、校验完整性并设为已发布；新建模块也可直接发布，失败不留下空模块。
- 不提供已发布副本与草稿副本，线上只读取当前已发布内容。
- 未发布模块允许保存不完整正文和未设置答案的题目。
- 发布要求至少一个章节、各章正文完整、已有题目均有题干和标准答案；允许章节无题。
- 下架仅改变状态，所有已保存内容继续可编辑。

数据库只保留当前内容。故障恢复依靠数据库备份，不以内容历史表替代备份。

## 前置学习模块

管理员可选择至多 12 个前置模块，并按推荐学习顺序排序。`module_prerequisites` 使用 `(module_id, prerequisite_id)` 主键及模块内唯一 position；拒绝重复、自身引用、无效模块和循环引用。

前置关系仅用于推荐，不增加访问门槛。后台可编排未发布模块；公开详情只返回当前已发布的前置模块，排序保持原配置。删除模块时自动清理指向它的推荐关系。它不是将多个模块集合为课程的“学习路线”功能。

修改前置关系与删除模块在同一内容事务中完成；内容写事务先取得固定 PostgreSQL advisory 锁，再取得模块行锁，确保并发更新 A→B 和 B→A 时仍拒绝成环，并保持一致的锁顺序。
