# Phase 2：真实认证与内容管理实施计划

日期：2026-10-23。状态：计划，尚未执行数据库迁移或部署。

> 后续执行入口：[当前实施计划：从内容接口到可用学习平台](post-auth-learning-plan.md)。认证与内容基础接口已在 43d771f 同步；以新计划为执行入口，不按本文重复建表或重做认证。

依据：[数据模型](learning-platform-v1.md)、[事务与接口契约](learning-platform-v1-flows.md)。

## 目标与范围

将 `web/` 已完成的页面接入真实服务端，逐步跑通账号、内容发布与学习闭环。新用户重新注册，不迁移 Go Control 身份。本阶段不接入 CLI／GUI 沙箱，不扩展会员、论坛、完整统计或节点管理。

## 1. 数据库与服务端基础

- 接入 PostgreSQL 与 Drizzle，建立 schema、迁移、连接池及环境配置。
- 先实现账号相关表，之后按业务闭环增加内容与进度表；不一次创建所有规划表。
- 为 Nuxt Nitro 建立统一的身份检查、管理员授权、输入校验与错误响应。
- 部署增加 Node/Nitro 服务与 PostgreSQL；首页继续预渲染，受限内容不放进静态产物。
- 使用独立开发／测试数据库验证迁移，不对现有 Go SQLite 做自动改动。

## 2. 真实账号体系

- 实现注册、邮箱验证、登录、退出、当前身份与找回／重置密码。
- Argon2id 密码哈希，HttpOnly Cookie Session；凭证只存摘要。
- 创建受控的管理员初始化命令，普通注册不能指定角色。
- 替换现有模拟认证；未接入的第三方入口保持关闭。
- 验证封禁、会话撤销、凭证过期与重复消费、登录限流和 CSRF／同源检查。

验收：新用户注册并验证邮箱后可登录，刷新或重启服务后 Session 按规则有效，退出与重置密码后旧 Session 失效。

## 3. 管理员内容编辑

- 实现模块列表、新建模块、章节编排、Markdown 编辑与预览。
- 实现题目与答案配置、草稿保存、并发修改冲突提示。
- 网页编辑和 Markdown 上传先跑通，GitHub 导入可后续加入。
- 保存草稿不改变已发布内容；未完成题目可保存，但不能发布。

## 4. 发布与学习阅读

- 实现发布／下架、发布校验、历史修订与审计。
- 接入学习模块列表、公开目录、正文阅读与私有附件授权。
- 校验公开章节可直接阅读，受限内容不进入公共缓存或公开页面 payload。
- 初期未解锁判断与学习接口共同开发，不能仅靠前端隐藏正文。

## 5. 测验与进度

- 实现服务端判题、幂等提交、章节完成与顺序解锁。
- 实现无测验章节显式完成、“继续学习”和模块进度。
- 验证并发答题不漏记完成，内容更新不撤销已有完成记录。

## 阶段验收

管理员创建包含两章和测验的模块 → 保存草稿 → 发布 → 用户注册登录 → 阅读公开首章 → 答对全部题 → 解锁第二章 → 刷新或重启后进度仍在。

通过上述流程后，再接路线编排、首页配置与其他后台管理。完整数据关系已在设计文档中预留，但实现顺序以可验证的业务流程为准。
