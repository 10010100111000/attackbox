## 2. 先补齐已有实现的边界

在扩展或正式开放学习功能前，以一个独立增量收口以下问题：

1. **认证邮件闭环**：目前 mailer 是 ConsoleMailer，注册与找回接口会返回原始验证／重置 token；生产响应与普通日志应移除这些值，测试通过专用测试邮件设施取得凭证。`pages/auth.vue` 目前只处理 login/register/recover，需要补 verify/reset 页面状态与成功／过期／失败交互。
2. **迁移唯一入口**：目前同时存在 Drizzle migrator 与自定义 SQL 文件遍历脚本、两个不同的 journal 约定，还有额外空占位迁移。选择一种迁移管理方式，在空测试库及已有版本测试库验证升级，不能直接删除已应用迁移或手工重建线上表。
3. **配置收口**：移除代码与脚本中的固定数据库凭证、默认答案 HMAC 密钥；缺少必要配置时明确失败。若已用于部署，按实际情况轮换相关凭据；不在文档中复制原值。
4. **发布完整性**：发布校验、当前草稿锁、封存与发布指针更新应处于一致的事务边界，补上空正文等发布校验、封存不可变与并发保存／发布验证。
5. **授权边界**：正文当前仅检查 authenticated 章节是否已登录，目录 isLocked 也未计算前置完成，不能标记为已实现“按顺序解锁”。读者响应补齐当前 moduleRevisionId / chapterRevisionId，供后续判题版本校验使用。
6. **API 反向代理**：保留现有 `/api/modules/*`、`/api/admin/modules/*`、`/api/admin/chapters/*`，核对路由均到 Nitro，不新建同义接口；旧 Go 路由继续按现状隔离。

这些是对已发现代码路径的具体补齐项，不是要求再次全面重构。可与开发环境页面搭建并行；受限阅读与测验不能在规则未完成时当作正式学习功能上线。

## 3. 第一轮页面：学习入口与正文

目标：让数据库里的已发布模块真正出现在已确认的学习界面。

### A1. 平台布局与模块列表（建议下一项具体编码任务）

- 新建 `layouts/learning.vue`、`pages/learn/index.vue`。
- 按学习平台原型实现平台导航、头像菜单、主题切换、移动端导航和模块卡片。
- 复用 `GET /api/modules` 与 `useAuth`；空列表显示真实空状态，不回退假模块。
- 登录成功后的“进入学习平台”改到 `/learn`，处理有效站内 returnTo；服务端验证权限，路由中间件只负责体验。
- SSR 身份请求正确转发 Cookie（例如 useRequestFetch），避免客户端登录、服务端却视为访客；私有状态不进入公共预渲染或共享缓存。
- 先用现有后台接口或独立开发种子建立一个两章测试模块，不在生产自动注入示例课程。

验收：登录 → 学习模块列表 → 刷新仍识别身份；访客可看已发布模块介绍；未发布模块不出现。桌面、手机、加载、空结果、失败状态都可体验。

### A2. 模块详情与章节正文

- 新建 `pages/learn/modules/[slug]/index.vue` 和 `pages/learn/modules/[slug]/[chapterSlug].vue`。
- 详情页显示介绍、章节目录与阅读入口；正文页复现可折叠目录、宽版文章、代码高亮、前后章导航及手机抽屉。
- 接现有详情／正文接口，统一 `{ ok, data }` 响应到前端 DTO，保留 HTTP 状态与业务错误，不能静默转为空内容。
- 提取 Markdown 渲染组件供后台预览复用。选择 markdown-it + Shiki，禁止危险 HTML，处理链接、代码溢出和图片布局。
- 私有图片与附件只有在完整授权接口可用时启用，不直接使用公共对象地址。
- CLI／GUI 暂留组件扩展位置，不假装已运行，不接真实环境。
- 本增量先在开发／测试环境验证；受限章节的正式顺序规则在第 5 节完成前不对外宣称已可用。

验收：从列表进入模块再进入章节；直接 URL 和刷新可用；正文无越权返回，目录操作正常，公开与登录受限状态正确。

## 4. 第二轮页面：管理员内容编辑

目标：管理员无需脚本或接口工具，即可维护同一份内容。

### B1. 管理布局、模块列表与新建

- 新建 `layouts/admin.vue`、`pages/admin/modules/index.vue`。
- 按管理原型实现模块列表、草稿／已发布状态、新建后进入编辑器。
- 接现有管理员列表／创建接口；普通用户进入后台有明确提示，接口独立 requireAdmin。
- 列表搜索／分页若现有接口不支持，再按实际页面需求补查询参数；避免前端假装分页、后台仍全量加载。

### B2. 模块与章节编辑器

- 新建 `pages/admin/modules/[id].vue`，包含模块资料、章节编排、正文编辑／预览、题目配置、保存／发布／下架。
- 编辑器第一版使用 Markdown 文本区 + 阅读预览；先不引入富文本、协同编辑或 GitHub 自动同步。
- 章节排序优先使用上下按钮，随后补拖动；后台预览直接复用学习正文渲染组件。
- 封面／附件上传、章节移除、标准答案保留与替换、排序接口等，以真实 UI 操作核对缺口，不因已有接口数量多而认为全部完成。
- 区分后台原始编辑态与保存 DTO；处理未保存离开、保存中／失败、409 冲突、发布校验定位。新建题目尚无答案时可存草稿，但发布不通过。

验收：后台新建两章模块 → 保存 → 重新打开仍在 → 发布 → 用户页立即看到新内容；修改草稿不影响已发布正文，普通用户不能访问后台数据。

## 5. 第三轮闭环：判题、进度与解锁

这时再新增真正缺少的三张表：`answer_attempts`、`chapter_completions`、`user_learning_activity`，使用追加迁移，不动已应用迁移。

### 后端

- 判题、无题章节完成、我的学习／继续学习接口；按既有内容 ID 与修订 ID 关联。
- 复用现有 HMAC 工具，补密钥版本管理与生产配置校验。
- 使用服务端身份和当前发布版本检查；幂等提交，同用户／模块进度写入串行化，所有题分次答对后也能正确记为完成。
- 公共章节直接可读；受限章节需登录且前置章节完成，或自身已有完成记录。
- 将同一授权规则用于正文、目录锁定、判题与私有附件，不由前端按钮决定权限。

### 前端

- `ChapterQuiz`：逐题输入、提交中、正确／错误提示、版本已更新提示；请求失败保留输入。
- 目录和模块页显示真实完成状态；首章完成后解锁下一章，“继续学习”定位实际章节。
- 无题章节显式标记完成；已有完成记录不因发布新版本而撤销。

验收：管理员创建并发布教程 → 新用户登录 → 阅读公开首章 → 全部题答对 → 解锁受限第二章 → 刷新和重启后进度仍在。直接调用接口不能绕过锁；并发答题与内容更新不产生错乱完成记录。

## 7. 工程拆分与验证方式

建议的页面组件边界：

```text
layouts/learning.vue、admin.vue
components/learning/
  ModuleCard、ChapterOutline、MarkdownArticle、ChapterQuiz、LearningWorkspace
components/admin/content/
  ModuleEditor、ChapterEditor、QuestionEditor、PublishAction
composables/
  useLearningModules、useChapter、useLearningProgress
server/services/
  content/（逐步提取已有保存、发布和读取逻辑）
  learning/（统一授权、判题、解锁）
```

不要求为了目录结构先改写所有现有路由；只在新增功能需要共享事务和规则时提取。先固定读者与管理员 DTO，避免把完整数据库行当页面接口。

每个编号任务单独交付：必要迁移、接口变更、可体验页面和对应验证。使用独立测试数据库；迁移检查覆盖空库与增量升级。远程测试文件有些会创建用户和修改内容，运行前确认目标是测试环境，不能直接以默认生产连接执行。

本轮是代码核查与计划更新，没有安装依赖、执行迁移、运行远程测试或修改线上服务。后续实现时再记录实际测试与验收结果。
